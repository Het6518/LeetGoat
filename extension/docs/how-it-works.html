How LeetGoat works

The pieces of the extension, how they talk to each other, and what happens step by step.

The big picture

A Chrome extension is several separate programs. LeetGoat has five, plus the browser storage they all share.

Why a separate “page bridge”?

Content scripts run in an isolated world: they can see LeetCode's HTML but not its JavaScript. The editor (Monaco) and LeetCode's network requests only exist in the page's own world, so a tiny plain-JS file runs there and relays what it sees.

public/bridge.js · src/lib/bridge.ts

Why a Shadow DOM?

LeetCode's CSS and ours would break each other. The whole UI is mounted inside a shadow root, so styles can't leak in or out. Tailwind's CSS is injected into that root as a string.

src/content/index.tsx · src/styles/content.css

Why storage, not messages?

Sidebar, popup and background never call each other for data. They all read chrome.storage.local and re-render when it changes, so every view stays in sync automatically.

src/hooks/useStorage.ts

Step-by-step flows

Pick a flow to see what happens, in order, and which file does each step.

You click a problem on LeetCode. LeetCode is a single-page app, so the page doesn't reload — LeetGoat has to notice the URL change itself.

  1. 1
    Detect the problem
    Every 0.6s the content script reads the URL. /problems/two-sum/ (or /contest/…/problems/…) → slug two-sum.
    src/hooks/usePage.ts → useProblemSlug
  2. 2
    Fetch problem data
    One GraphQL request: title, difficulty, topics, acceptance, hints, similar problems, constraints text, and whether you've solved it.
    src/api/leetcode.ts → fetchProblem
  3. 3
    Create / update the problem record
    Saves p:two-sum in storage with the latest title and difficulty.
    src/lib/storage.ts → touchProblem
  4. 4
    Start the focus timer
    Auto-starts if the problem is unsolved or due for review. Pauses when you switch tabs, saves every 15s, survives reloads.
    src/hooks/useTimer.ts
  5. 5
    Build the Solve tab
    Constraints are parsed (e.g. n ≤ 10⁵ → “aim for O(n log n)”), hints are revealed one at a time, similar problems show your solved status.
    src/lib/constraints.ts · src/components/solve/*

You press Submit. Two independent detectors race; whichever sees the verdict first wins, and the other is ignored.

  1. 1
    LeetCode polls for the result
    After submitting, LeetCode's own code repeatedly calls /submissions/detail/<id>/check/ (or /v2/check/) until the judge finishes.
    LeetCode's page code
  2. 2
    The bridge reads that response
    bridge.js wrapped fetch and XMLHttpRequest before LeetCode loaded. When a response says state: SUCCESS (and AI judging is done), it maps the status code — 10 Accepted, 11 Wrong Answer, 14 TLE, 15 Runtime Error, 20 Compile Error — and posts it to the content script.
    public/bridge.js → reportCheck
  3. 3
    Backup: read the screen
    Every 0.8s the content script also looks at the result panel (the Accepted heading, or a rejected heading when a submission is open). Same verdict, used only if step 2 missed it.
    src/hooks/usePage.ts → useSubmissionWatcher
  4. 4
    One handler, de-duplicated by submission id
    src/content/App.tsx → handleVerdict
    AcceptedBig green ACCEPTED · Well done! 🎉 + fanfare. Timer pauses. Problem marked solved, sidebar opens with the rating prompt.
    Anything elseBig red REJECTED · Wrong Answer (or TLE, etc.) + “faaah”. Fail counter for this attempt goes up.
  5. 5
    Sound
    Built-in sounds are synthesized live with the Web Audio API (no audio files). If you uploaded your own clip in Settings, that plays instead.
    src/lib/sounds.ts · src/content/VerdictBanner.tsx

Spaced repetition: solved problems come back right before you'd forget them.

  1. 1
    You rate the attempt
    Needed help · Struggled · Solid · Easy. One is pre-selected from what happened: time vs your target, wrong submissions, hints used, outside pastes.
    src/components/solve/RatePrompt.tsx · src/lib/srs.ts → suggestRating
  2. 2
    Schedule the next review
    An SM-2 style formula sets the next date: first “Solid” → 4 days, then 10, then growing by your “ease”. “Needed help” resets to 1 day.
    src/lib/srs.ts → schedule · src/lib/actions.ts → rateProblem
  3. 3
    Toolbar badge
    The background worker counts due reviews whenever storage changes (and every 30 minutes) and shows the number on the goat icon.
    src/background/index.ts → refreshBadge
  4. 4
    Review it
    Open it from the Review tab or popup. A “Review time” banner appears; the timer starts fresh; rating again pushes the next date further out.
    src/components/shared/ReviewList.tsx

On any profile page (/u/<name>/) tap the shield in the dock. Only available away from problem pages.

  1. 1
    Load contest history
    GraphQL userContestRankingHistory → every contest the account attended (title, rating change, problems solved).
    src/api/leetcode.ts → fetchContestHistory
  2. 2
    Get each contest's problems
    src/api/leetcode.ts → fetchContestQuestions
  3. 3
    Read LeetCode's Code Replay
    One GraphQL request per contest asks userContestReplayEvents for all 4 problems. Each event has a type: 7 = typing, 5 = submit, 10 = External Paste (with the pasted text).
    src/api/leetcode.ts → fetchReplayEvents
  4. 4
    Judge each problem → contest
    A problem is External paste if any paste is over 200 characters. A contest is flagged if any of its problems is.
    src/lib/contest.ts → analyzeProblem
  5. 5
    Final verdict
    Likely a cheaterFlagged contests ≥ half of contests taken.
    Not a cheaterFewer than half. (No replay data at all → “Nothing to check”.)
    src/lib/contest.ts → scanAccount · src/components/contest/AccountPanel.tsx

Insert a template (union-find, Dijkstra, binary search…) at your cursor.

  1. 1
    Open the palette
    Press Alt+S (Chrome sends it to the background worker, which forwards it to the tab) or click { } in the dock.
    src/background/index.ts → commands · src/content/App.tsx
  2. 2
    Filter by your language
    Asks the bridge which language the editor is in, then shows matching built-ins plus your own snippets.
    src/components/snippets/SnippetPalette.tsx · src/data/snippets.ts
  3. 3
    Insert
    Content script posts insert → bridge calls Monaco's executeEdits at the cursor, matching indentation. If the editor can't be reached, the code is copied to your clipboard instead.
    src/lib/bridge.ts → insertIntoEditor · public/bridge.js

Keeps your practice honest: pasting a solution shouldn't count as “I solved it”.

  1. 1
    Remember what you copy
    The bridge notes text you copy inside the page (Ctrl+C in the editor, or from the problem).
  2. 2
    Catch pastes in the editor
    Monaco's onDidPaste fires. Pastes of 40+ characters that you didn't just copy on the page count as external.
    public/bridge.js → attach
  3. 3
    Record it for this attempt
    A toast appears, the Solve tab shows a warning, and a paste of 200+ characters pre-selects “Needed help” when you rate.
    src/lib/actions.ts → recordPaste · src/lib/srs.ts

Grind 75, NeetCode 150 and Blind 75, with your real solved status.

    Lists are bundled
    Only problem slugs and sections ship with the extension (all 168 verified to exist).

  2. 2

What happens when Chrome starts or you click “Reload” on the extension.

  1. 1
    Background worker wakes up
    onInstalled / onStartup fire.
    src/background/index.ts
  2. 2
    Register the page bridge
    Registers bridge.js to run in the page's own world at document_start — before LeetCode's scripts, so its fetch hook is in place. This is why you must refresh LeetCode tabs after reloading the extension.
  3. 3
    Badge alarm
    A 30-minute alarm keeps the due-review count fresh even when nothing changes.
  4. 4
    On each LeetCode page
    The content script mounts the Shadow DOM, registers Tailwind's CSS properties on the page, and renders the dock.
    src/content/index.tsx

What's stored

Everything lives in your browser only (chrome.storage.local). Export/import from Settings.

KeyContents
p:<slug>One per problem: title, difficulty, topics, solved date, time spent, attempts, current attempt (time / hints / fails / pasted), review schedule, rating history.
settingsTheme, target times, toggles, sound choices, chosen study plan.
activityPer-day counts of solves, reviews and time.
planmetaCached titles, difficulty and solved status for plan problems.
snippetsYour own snippet templates.
sound:success / sound:failUploaded audio clips, if any.
